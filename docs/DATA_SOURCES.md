# 输入源说明与边界

所有输入源最终都产出同一结构：`Article(title, date, url, mid, digest)`。
分析层与输入源完全解耦，新增来源不需要改报告逻辑。

| 输入源 | 数据来源 | 联网 | 能拿到日期 | 能拿到链接 | 稳定性 |
|---|---|---|---|---|---|
| `csv` | 自备 CSV / URL 清单 | 否 | 取决于文件 | 是 | 最高 |
| `chatlog` | 本机聊天记录导出 | 否 | 部分 | 是 | 高 |
| `sogou` | 公开搜索结果 | 是 | 是 | 否 | 低，有反爬 |
| `session` | 完整历史消息接口 | 是 | 是 | 是 | 取决于会话有效性 |

---

## csv（默认）

零配置路径。仓库自带 `examples/demo_articles.csv`，也可以传自己的文件。

- 带表头：识别 `date,title,url,mid,digest`，列名大小写不敏感，缺列留空即可。
- 无表头：第一列当作 URL。
- 纯文本：一行一个 `mp.weixin.qq.com/s?...` 链接。

`mid` 会从 URL 自动解析，不需要单独提供——它是群发序号，比搜索结果的显示日期更适合排序。

## chatlog

扫描指定的文件或目录（支持 `*.json / *.txt / *.md / *.xml / *.csv`，可递归），
抽取其中的公众号文章卡片链接，并尝试从邻近的 `<title>` 和日期字符串补齐元信息。

只读本机文件，不联网。适合把「我在聊天里转发过的文章」整理成时间线。

## sogou

用关键词翻检索结果页，解析公众号名与发布时间戳，只用来**补标题和日期**。

- 它的 `/link?url=...` 跳转有反爬，**不要**指望用它拿到真实文章链接。
- 任何网络异常都降级为空列表，不会中断主流程。
- 关键词命中范围有限，容易把「最近的日更期」误判成整个账号的全部历史；
  结论请以 `session` 或自备完整清单为准。

## session（`--full`）

调用历史消息接口自动翻页，是唯一能拿到**全量图文群发**的输入源。
详见 [`SESSION_PROVIDER.md`](SESSION_PROVIDER.md)。

---

## 降级策略

```
session 拿不到凭证
   ↓
sogou 补标题/日期（可能被反爬）
   ↓
chatlog 从本机聊天导出抽卡片
   ↓
csv 手动整理 / 别人分享的清单
```

分析、月度聚合、阶段划分、报告生成在**任何一级**都照常工作。
这就是为什么默认路径不依赖凭证：clone 下来第一次运行一定有结果。

---

## 数据边界

- 只处理公开文章页面的元信息，不抓取或分发正文。
- 示例数据不含摘要、正文、凭证或个人信息。
- `session` 仅限本人设备本人账号，遵守平台服务条款，不高频请求。

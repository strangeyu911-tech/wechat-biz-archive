# extras / collect_session.py · 实验性

> **实验性、可选、默认不参与主流程。**
> 主项目（`wba.py`）不依赖这个目录；删掉它，零配置路径和所有其它输入源照常工作。

## 它做什么

在本机 Windows 桌面客户端已登录的前提下，读取客户端进程自己产生的运行时请求，
提取它自己生成的会话参数（`uin / key / pass_ticket / appmsg_token`），
写成本地 JSON 供主项目的 `--full` 模式使用。

```bash
# 先确认本机客户端已登录、打开过目标公众号
python extras/collect_session.py --biz <__biz>

# 再用主项目跑完整历史
python wba.py --full --biz <__biz> --credentials credentials.json --out full_report.md
```

```bash
# 只测解析逻辑，不碰任何进程
python extras/collect_session.py --self-test
```

参数说明：

| 参数 | 说明 |
|---|---|
| `--out` | 输出路径，默认当前目录 `credentials.json`（已被 `.gitignore` 排除） |
| `--biz` | 可选，填了会调用主包的 `history.probe()` 验证哪组候选当前有效 |
| `--timeout` | 扫描时间预算，默认 60 秒 |
| `--self-test` | 只跑解析单测，不读进程 |

## 设计上的取舍

- **不含任何本机配置**：进程名、PID、路径全部运行时发现；没有硬编码的账号、密钥、
  数据目录、用户标识或示例值。仓库里搜不到任何真实凭证。
- **不打印凭证内容**：只输出「扫了几个进程、多少 MB、找到几组候选」，不显示参数值。
- **不联网上传**：唯一的出向请求是 `--biz` 时向官方接口做一次有效性探测。
- **一次一组不够**：客户端会同时存在多组参数，实测可能十几组里只有一组有效，
  所以脚本会去重收集全部候选，由主包的 `probe()` 逐组试探。
- **不保存长期凭证**：参数几小时过期，脚本每次重新收集，用完请删除输出文件。

## 边界

- 仅限**本人设备、本人账号**，用于整理自己能访问到的公开内容。
- 遵守对应平台的服务条款；不要高频批量请求，不要商业分发。
- 该目录是实验性实现，客户端版本变化可能导致失效。
  排查思路与已验证不可行的路径清单见 [`../docs/SESSION_PROVIDER.md`](../docs/SESSION_PROVIDER.md)。
- 输出文件 `credentials.json` 属于本机私密数据，**绝不提交、绝不贴到对话或日志里**。
